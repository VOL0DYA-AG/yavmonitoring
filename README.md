# Имитатор сигналов

Веб-приложение генерирует значения датчиков, дискретных сигналов и счётчиков и публикует их в MQTT. Считает не браузер, а процесс Node.js: вкладку можно закрыть, публикация продолжится. Состояние пишется на диск, после перезапуска потоки и счётчики продолжаются с того же места.

Интерфейс собран по визуальной системе Sentri из [Awesome DESIGN.md](https://github.com/VoltAgent/awesome-design-md): тёмный холст `#1f1633`, карточки `#150f23`, светлые поля, одна лаймовая плашка в заголовке. Правила системы лежат в `DESIGN.md`.

## Что можно задать

- тип сигнала: температура, давление, уровень, расход, влажность, напряжение, ток, дискретный, счётчик или произвольный;
- диапазон значений;
- тип генерации;
- MQTT-топик;
- период публикации (от 0,1 с до суток);
- число знаков после запятой (0–6).

Дополнительно: единица измерения, QoS, retain, формат сообщения (JSON или голое число), параметры выбранной генерации (период волны, скважность, шаг счётчика и другие).

У каждого потока есть пауза, изменение параметров, удаление и отдельное окно с живым значением, графиком и последними сообщениями.

## Требования

- Linux (проверено на Debian/Ubuntu);
- Node.js 18 или новее (в разработке использовался 22);
- MQTT-брокер, например Mosquitto. Приложение само брокером не является.

Порт веб-интерфейса по умолчанию — `8080`. У приложения нет входа и пароля. Не открывайте этот порт в интернет. Пароль брокера хранится в `state.json` на сервере.

## Скачать и запустить

### 1. Node.js

Проверьте версию:

```bash
node -v
npm -v
```

Если команды нет или версия меньше 18, поставьте Node.js 22 в `/usr/local`:

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl xz-utils
curl -fsSL https://nodejs.org/dist/v22.14.0/node-v22.14.0-linux-x64.tar.xz -o /tmp/node.tar.xz
sudo tar -xJf /tmp/node.tar.xz -C /usr/local --strip-components=1
node -v
npm -v
```

На Ubuntu 24.04 часто хватает пакетов дистрибутива: `sudo apt-get install -y nodejs npm`. Версия всё равно должна быть 18+.

### 2. Код

```bash
git clone https://github.com/VOL0DYA-AG/yavmonitoring.git
cd yavmonitoring
git checkout cursor/mqtt-signal-simulator-884d
npm ci --omit=dev
```

Ветка `main` пока содержит только короткий README. Приложение и `package-lock.json` лежат в `cursor/mqtt-signal-simulator-884d`. Без этого файла `npm ci` завершается с `EUSAGE`. После вливания в `main` строку `git checkout` можно не выполнять: достаточно клона и `npm ci --omit=dev`.

`npm ci` ставит ровно те версии, что в `package-lock.json`. Нужен доступ к registry.npmjs.org. Если у сервера нет интернета, выполните `npm ci --omit=dev` на машине с сетью и скопируйте каталог вместе с `node_modules`. Команды `node` и `npm` должны быть из одной установки Node.js 18+.

### 3. Брокер, если его ещё нет

```bash
sudo apt-get install -y mosquitto mosquitto-clients
sudo systemctl enable --now mosquitto
mosquitto_sub -h 127.0.0.1 -t 'plant/#' -v
```

Последняя команда ждёт сообщения. Её можно оставить в отдельном терминале.

### 4. Пробный запуск

```bash
DATA_DIR=/var/lib/yavmonitoring PORT=8080 node src/server.js
```

Если каталога данных ещё нет:

```bash
sudo mkdir -p /var/lib/yavmonitoring
sudo chown "$USER":"$USER" /var/lib/yavmonitoring
chmod 700 /var/lib/yavmonitoring
```

Откройте в браузере `http://АДРЕС-СЕРВЕРА:8080`. С этой же машины: `http://127.0.0.1:8080`.

Проверка процесса:

```bash
curl -s http://127.0.0.1:8080/api/health
```

Ожидается JSON с `"ok": true`. Остановка пробного запуска — Ctrl+C: процесс сохранит состояние и закроет MQTT.

### 5. Служба, которая живёт неделями

Так приложение поднимается после перезагрузки сервера и само перезапускается, если процесс упал.

```bash
sudo useradd --system --home /opt/yavmonitoring --shell /usr/sbin/nologin yavmon || true
sudo mkdir -p /opt/yavmonitoring /var/lib/yavmonitoring
sudo rsync -a --delete --exclude data --exclude .git ./ /opt/yavmonitoring/
sudo chown -R yavmon:yavmon /opt/yavmonitoring /var/lib/yavmonitoring
sudo chmod 700 /var/lib/yavmonitoring
sudo -u yavmon npm ci --omit=dev --prefix /opt/yavmonitoring
sudo cp /opt/yavmonitoring/deploy/yavmonitoring.service /etc/systemd/system/yavmonitoring.service
```

Если `node` лежит не в `/usr/bin/node`, поправьте `ExecStart` в unit-файле (`command -v node`).

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now yavmonitoring
sudo systemctl status yavmonitoring
journalctl -u yavmonitoring -f
```

В unit-файле уже стоит `Restart=always` и `StartLimitIntervalSec=0`: служба не перестаёт подниматься после серии сбоев. Память ограничена 512 МБ; для этого приложения этого достаточно, а утечка не займёт весь сервер.

Открыть интерфейс в локальной сети:

```bash
sudo ufw allow 8080/tcp
```

Делайте это только в доверенной сети.

## Как пользоваться

1. Сверху — подключение к брокеру: протокол, хост, порт, пользователь, пароль, Client ID. Кнопка **Подключить**. Рядом статус: нет соединения, подключение, подключен, переподключение или ошибка.
2. Ниже — новый поток. Заполните тип сигнала, генерацию, диапазон, знаки после запятой, период и топик. Кнопка **Добавить поток**. Публикация начинается сразу.
3. Дальше список потоков. **Пауза** / **Пуск**, **Открыть поток**, **Изменить**, **Удалить**.

**Открыть поток** поднимает отдельное окно с текущим значением, графиком и таблицей сообщений. Закрытие этого окна поток не останавливает. Если браузер запретил всплывающие окна, откроется вкладка.

Смена типа сигнала в форме нового потока подставляет типичный диапазон. Перед добавлением любые поля можно поменять. В окне редактирования диапазон сам не переписывается.

Пока кнопка брокера показывает **Подключен**, правка полей включает **Переподключить**: новые параметры применятся по нажатию. **Отключить** запоминается: после перезапуска служба сама к брокеру не полезет. Если оборвать процесс, не нажимая «Отключить», при старте она подключится снова.

## Типы генерации

| Тип | Поведение |
|---|---|
| Постоянное | Одно значение в каждом сообщении |
| Равномерный случайный | Каждая точка равновероятна внутри диапазона |
| Нормальный шум | Колокол вокруг середины диапазона, края редки |
| Случайное блуждание | Небольшой случайный шаг, не больше заданной доли диапазона |
| Синусоида | Плавная волна от минимума к максимуму. Фаза привязана к часам |
| Прямоугольный | Минимум и максимум со скважностью |
| Пила | Линейный рост и резкий сброс |
| Линейный рост | От минимума к максимуму за заданное время, затем повтор или удержание |
| Счётчик | Первое значение — старт, дальше прибавляется шаг. На максимуме можно остановиться или начать сначала |

Смена типа генерации у уже созданного потока обнуляет фазу, блуждание и накопленный счётчик. Пауза и правка остальных полей счётчик не сбрасывают.

## Сообщения MQTT

JSON, два знака после запятой:

```json
{"ts":"2026-09-30T20:00:00.000Z","value":21.50,"name":"Давление линии","unit":"бар","quality":"good"}
```

Формат «только число» публикует строку `21.50` без JSON. Точность на выходе совпадает с полем «знаков после запятой».

В топике нельзя использовать `+` и `#`: это шаблоны подписки, в них публиковать нельзя.

QoS 0 не копит очередь. При QoS 1 или 2 служба держит не больше одной неподтверждённой публикации на поток и не отправляет все промежуточные точки, если брокер не успевает. Для многонедельной работы оставляйте QoS 0, если подписчику не нужно подтверждение каждой точки.

## Если брокер недоступен

Генерация не останавливается: в карточке видно последнее значение и счётчик «не доставлено». Сообщения не складываются в память и не выплёскиваются пачкой, когда связь вернётся. Клиент MQTT переподключается сам, раз в 5 секунд, и пишет в журнал не чаще раза в минуту.

Если процесс надолго замер и пропустил несколько периодов, после пробуждения уходит одно актуальное значение, а не вся пропущенная история. Число таких пропусков видно в карточке.

Состояние (настройки, позиция счётчика, фаза, счётчики отправок) пишется сразу при изменении настроек и затем каждые 30 секунд. Запись атомарная: временный файл и `rename`. `kill -9` может потерять не больше последних 30 секунд счётчика. Обычная остановка через systemd или Ctrl+C сохраняет состояние до выхода.

История графика после перезапуска пустая и наполняется заново. В памяти хранится не больше 500 точек на поток.

Повреждённый `state.json` не роняет службу: файл переименовывается в `state.json.bak-…`, процесс стартует с пустым списком и пишет об этом в журнал.

Раз в 10 минут в журнал уходит строка `stats`: сколько потоков, сколько отправлено и сколько не доставлено.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HOST` | `0.0.0.0` | Адрес HTTP |
| `PORT` | `8080` | Порт HTTP |
| `DATA_DIR` | `./data` | Каталог с `state.json` |
| `NODE_ENV` | пусто | В службе стоит `production` |

Файл состояния: `$DATA_DIR/state.json`, права `0600`.

## Обновление

Данные лежат отдельно от кода, `git pull` их не трогает.

```bash
sudo rsync -a --delete --exclude data --exclude .git ./ /opt/yavmonitoring/
sudo chown -R yavmon:yavmon /opt/yavmonitoring
sudo -u yavmon npm ci --omit=dev --prefix /opt/yavmonitoring
sudo systemctl restart yavmonitoring
```

Команду rsync запускайте из свежего клона, не из `/opt/yavmonitoring`.

## Проверка

```bash
npm ci
npm test
```

Тесты гоняют генераторы, расписание без пачки сообщений после простоя, сохранение счётчика, HTTP API и живую публикацию в MQTT.
